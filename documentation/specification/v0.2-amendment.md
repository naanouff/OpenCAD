# CADOM Spec v0.2 — amendment notes

**Date:** 2026-09-14  
**Base:** v0.1 draft frozen  
**Change type:** additive minor (`version_minor = 2`)

## What changed

- New `AssetKind` values: `CADOMESH`, `CADOMPART`, `CADOMAT`
- Spec §4.8–4.10: roles of `.cadomesh` (tessellated mesh), `.cadompart` (parametric part data), `.cadomat` (Khronos-aligned PBR material)
- `Override.material_ref` **SHOULD** point at a `CADOMAT` asset id when using native materials

## Deferred (schemas still TBD)

1. Normative binary layout of `.cadomesh`
2. Normative parametric schema of `.cadompart`
3. Normative container encoding of `.cadomat` (semantics track glTF 2.0 metallic-roughness)
4. Multi-asset binding on a single node → addressed in **v0.3** (`asset_bindings`)

## Compatibility

- v0.1 readers that ignore unknown enum values **MAY** still round-trip assets if unknown-field/enum policy allows; strict readers **SHOULD** warn on kinds `5–7` when implementing only v0.1.
- Complete CADOM toolchains **SHOULD** implement the three native kinds.
